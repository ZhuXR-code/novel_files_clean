# iOS App Review 申诉模板（资质/备案说明备用）

> 用途：当 App Store Connect 审核被拒，且拒因涉及「需要相关资质 / ICP 备案 / 电信经营许可证 /
> 互联网信息服务许可」等情况时，可作为回复审核意见或提交 App Review Board 申诉的参考模板。
>
> 重要前提：本 App（文包整理清理助手）是**纯本地、不联网的文件管理工具**，内购走苹果
> StoreKit 2 买断制，不涉及任何自建联网服务，因此按现行规定**无需 ICP 备案、无需电信业务
> 经营许可证**。本模板仅在被拒时按需填写使用，正常提审无需主动提交。

---

## 一、适用场景判断

| 拒因线索 | 是否适用本模板 |
|---|---|
| 审核意见提到「需提供 ICP 备案号 / 增值电信业务经营许可证 / 互联网信息服务许可」 | ✅ 适用 |
| 拒因是崩溃、隐私、设计、占位内容等（Guideline 2.1 / 5.1.1 / 4.x） | ❌ 不适用，按对应问题修复 |
| 拒因是内购绕过 IAP（Guideline 3.1.1） | ❌ 不适用，本 App 已用 IAP，应说明合规 |
| 拒因是金融 / 医疗 / 新闻等特许行业资质 | ❌ 不适用，本 App 不属于此类 |

## 二、回复审核意见模板（被拒后直接回复发件人 / App Store Connect 内回复）

```
尊敬的 App Review 团队：

感谢您对「文包整理清理助手」的审核。关于您提出的资质 / 备案相关要求，我们说明如下：

1. 本 App 是一款纯本地的 TXT 文包整理工具，核心功能（扫描、去重、归并、批量重命名、
   文库管理）全部在设备端完成，**完全不联网、不上传任何用户数据、不提供任何在线服务**。

2. 根据《互联网信息服务管理办法》，ICP 备案及增值电信业务经营许可证的适用前提是
   「经营接入公网的互联网信息服务」。本 App 不运营任何服务器或在线平台，因此不属于
   需备案或办证的范畴。

3. 应用内的「永久解锁」采用 Apple 官方 StoreKit 2 非消耗型内购（产品 ID：
   com.booksclean.app.unlock），资金结算由 Apple 处理，我们未接入任何第三方支付或
   自建支付通道，完全符合 Guideline 3.1.1。

4. 隐私方面：本 App 不收集、不上传任何个人信息，已提供独立隐私政策
   （https://zhuxr-code.github.io/novel_files_clean/privacy_policy.html）。

基于以上，本 App 为离线单机工具，不涉及需行政许可的互联网信息服务，恳请审核团队
据此重新评估。如需我们补充任何材料，请随时告知。

此致
敬礼
```

## 三、App Review Board 申诉模板（对审核结果不服，正式申诉）

```

提出申诉。

【驳回涉及的 Guideline】
<粘贴审核给出的 Guideline 编号，例如：Guideline 1.3 / 5.1 等>

【事实说明】
- 产品定位：面向网文读者的本地 TXT 文包整理工具，所有功能在设备端运行。
- 联网情况：App 不发起任何网络请求，不向外部服务器传输数据，无后端服务。
- 内购方式：通过 Apple 官方 StoreKit 2 实现一次性买断（非消耗型项目），符合
  Guideline 3.1.1，未使用任何第三方支付。
- 资质情况：因 App 不提供互联网信息服务，依《互联网信息服务管理办法》无需办理 ICP
  备案或增值电信业务经营许可证。

【申诉请求】
恳请 Board 依据 App 实际为离线单机工具这一事实，重新审议驳回决定，并给予上架许可。
我们乐意配合提供任何补充说明。

联系方式：<你的邮箱 / 开发者账号邮箱>
```

## 四、使用说明

1. 本模板为**备用**，正常情况下（纯本地工具 + IAP 买断）一般不会因资质问题被拒。
2. 被拒后先读清拒因编号，确认属于「资质/备案」类再套用本模板。
3. 把 `<填写你的 Apple ID>`、`<你的邮箱>` 等占位替换为真实信息。
4. 隐私政策 URL 若后续变更，请同步更新模板中的链接。
5. 若被拒原因与资质无关（如崩溃、隐私弹窗、截图不符），请勿套用本模板，应针对性修复。
